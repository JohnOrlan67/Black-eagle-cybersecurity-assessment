# Lab 02 — Tank-Level Alarms and Sensor-Fault Detection

## Overview

This lab extends Lab 01's simulated tank-level controller with two process alarms and a sensor-fault flag. It was implemented in OpenPLC using Structured Text (ST) and validated with the debugger by applying simulated level values.

**Environment:** OpenPLC Editor and Simulator  
**Language:** Structured Text (IEC 61131-3)  
**Scope:** Software simulation only. No physical tank, transmitter, pump, or alarm device was connected.

## Learning objectives

- Distinguish a process alarm from a sensor fault.
- Use conditional logic to detect low and high tank-level conditions.
- Detect simulated measurements outside a configured 0–100% range.
- Prevent normal level alarms from being asserted when the measurement is flagged invalid.
- Observe and record PLC variable states in the debugger.
- Identify limitations that would need engineering review before any real deployment.

## Variables

| Variable | Type | Initial value | Purpose |
|---|---|---|---|
| `Level` | `REAL` | `0.0` | Simulated tank level as a percentage |
| `Pump` | `BOOL` | `FALSE` | Simulated pump command |
| `LowLevelAlarm` | `BOOL` | `FALSE` | Indicates a valid level at or below 10% |
| `HighLevelAlarm` | `BOOL` | `FALSE` | Indicates a valid level at or above 90% |
| `SensorFault` | `BOOL` | `FALSE` | Indicates a simulated level reading below 0% or above 100% |

## Logic and configured thresholds

- A reading below 0% or above 100% sets `SensorFault` to `TRUE`.
- When `SensorFault` is `TRUE`, both normal level alarms are cleared.
- For a valid reading, `LowLevelAlarm` is active at `Level <= 10.0`.
- For a valid reading, `HighLevelAlarm` is active at `Level >= 90.0`.
- Pump control is evaluated only when `SensorFault` is `FALSE`: the pump command turns ON at or below 20%, turns OFF at or above 80%, and retains its previous state between the thresholds.
- While `SensorFault` is `TRUE`, the program retains the previous pump command. This is a training choice, not a generally safe response for every real process.

These values are chosen for this exercise; they are not universal industrial setpoints or alarm standards.

## Structured Text program

The complete source is in [`Tank_Level_Alarm_Control.st`](Tank_Level_Alarm_Control.st). In the OpenPLC Editor used for this lab, declarations were managed in the upper declaration pane and the program body in the lower code pane. The file below shows the combined IEC Structured Text representation.

```iecst
PROGRAM main
VAR
    Level : REAL := 0.0;
    Pump : BOOL := FALSE;
    LowLevelAlarm : BOOL := FALSE;
    HighLevelAlarm : BOOL := FALSE;
    SensorFault : BOOL := FALSE;
END_VAR

(* 1. Detect invalid tank-level readings *)
IF (Level < 0.0) OR (Level > 100.0) THEN
    SensorFault := TRUE;
ELSE
    SensorFault := FALSE;
END_IF;

(* 2. Update alarms only when the sensor is valid *)
IF SensorFault THEN
    LowLevelAlarm := FALSE;
    HighLevelAlarm := FALSE;
ELSE
    IF Level <= 10.0 THEN
        LowLevelAlarm := TRUE;
    ELSE
        LowLevelAlarm := FALSE;
    END_IF;

    IF Level >= 90.0 THEN
        HighLevelAlarm := TRUE;
    ELSE
        HighLevelAlarm := FALSE;
    END_IF;
END_IF;

(* 3. Control the pump only when the sensor is valid *)
IF NOT SensorFault THEN
    IF Level <= 20.0 THEN
        Pump := TRUE;
    ELSIF Level >= 80.0 THEN
        Pump := FALSE;
    END_IF;
END_IF;

END_PROGRAM
```

## Validation results

The following observed debugger values matched the programmed behaviour in the simulator.

| Test | Simulated level | Pump | Low alarm | High alarm | Sensor fault | Result |
|---|---:|---|---|---|---|---|
| 1 — Low-level condition | 8% | TRUE | TRUE | FALSE | FALSE | PASS |
| 2 — High-level condition | 95% | FALSE | FALSE | TRUE | FALSE | PASS |
| 3 — Above valid range | 105% | FALSE | FALSE | FALSE | TRUE | PASS |
| 4 — Below valid range | -5% | FALSE | FALSE | FALSE | TRUE | PASS |
| 5 — Lower valid boundary | 0% | TRUE | TRUE | FALSE | FALSE | PASS |
| 6 — Upper valid boundary | 100% | FALSE | FALSE | TRUE | FALSE | PASS |

**Result:** 6 of 6 observed test cases matched the expected program logic. This is a functional check of simulated values, not a formal verification or a test of physical instrumentation.

## What this lab demonstrates

A process alarm and a sensor fault represent different conditions. For example, 95% is a valid but high measurement, so the high-level alarm activates. A reading of 105% is outside the configured range, so the sensor-fault flag activates and normal level alarms are cleared.

The lower and upper boundary checks also confirm that exactly 0% and exactly 100% are treated as valid by the implemented conditions.

## Limitations and safety considerations

- The `Level` value was forced in the debugger; it was not generated by a physical level transmitter.
- `Pump` represents a logical command only. Physical pump operation and feedback were not tested.
- The fault strategy retains the previous pump command. In a real installation, the appropriate response must be determined through process hazard and risk analysis.
- Clearing normal level alarms during a sensor fault must not be treated as a substitute for an independent fault alarm or operator indication in a real system.
- This exercise does not implement or validate a Safety Instrumented System (SIS), interlocks, electrical protection, or a safety function.
- All thresholds are illustrative and must not be copied into a real process without engineering review.

2. Confirm the five variable declarations and enter the program body.
3. Save and start the project.
4. Open the debugger's Variables view.
5. Apply the six test values shown in the validation table, observing all five variables after each value.
6. Capture screenshots of the program and test results.
7. Release any forced values if the editor offers that option, then stop the simulator.
